# 记忆架构

## 四层

| 层 | 文件 | 更新频率 | 读取时机 | 放什么 |
|---|---|---|---|---|
| 状态 | `STATUS.md` | 每次整理 | 每会话自动注入 | 最近发生的事、当前在忙什么、待办 |
| 属性 | `MEMORY.md` | 属性变化时 | 每会话自动注入 | 作息、喜好、忌讳、长期目标 |
| 细节 | `记忆库/*.md` | 有新内容时 | 按索引读取 | 一件事的完整记录 |
| 叙事 | `回忆录-*.md` | 有值得记的事时 | 很少读 | 按时间顺序写成故事的经历 |

前两层是常驻的。后两层不进上下文，常驻文件里写一行指向它们的路径，用到时按路径去读。

## 状态层

状态层回答的是"现在"。【称呼】此刻在做什么、上次聊到哪、答应了什么还没做、有没有漏掉的心跳。

这一层更新最频繁，每次整理都要动。写法上要极简：每条一句话说清，需要细节的地方写一行索引。

判断一条要不要留在这一层，标准是"这条信息现在还有没有用"。事情办完了、话题过去了，就该移走或者删掉。

## 属性层

属性层回答的是"【称呼】是谁"。作息、喜好、忌讳、目标、家庭情况。

这一层只在属性真的变化时才改。没有变化的整理轮次，这一层不动。

写属性层容易犯的毛病是把状态写成属性：【称呼】今天心情不好是状态，一被夸就解释半天才是属性。

## 文件库

文件库放的是细节：一件事的完整过程、一次长谈的原话、一个项目的来龙去脉。

一个文件一件事，文件名就是这件事的名字。按时间倒序记，新的写在上面。

文件库的规模控制在几十到几百份。超过这个规模时按主题合并。

## 叙事层

叙事层放的是值得记住的经历，用故事写，保留当场说过的话和当时的气氛。

这一层写的是经历，不是资料，篇幅可以长一些。

## 索引

索引是常驻文件和文件库之间的连接，写法是一行"详情在 `记忆库/xxx.md`"。

留不留索引的判断标准只有一条：我不主动去读它，会不会误事。

- 会误事：近期要用、重要、忘了要出问题的，留索引
- 不会误事：有价值但近期用不上，只进文件库

索引过多会让常驻文件重新膨胀，索引过少会导致该用到的信息查不到。

## 拆分

单个记忆文件超过 15KB 时，按话题拆成两个或多个文件，同时把指向它的索引全部改掉。

按话题拆分，不按时间平均分。拆分后每个文件要能独立说明一件事。

## 生命周期

| 内容 | 它会经历什么 |
|---|---|
| 状态条目 | 出现 → 反复更新 → 事情办完 → 移进文件库或删除 |
| 属性条目 | 写入 → 长期不变 → 变了才改 |
| 文件库条目 | 新建 → 追加细节 → 太大就拆分 → 长期保留 |
| 叙事条目 | 写入 → 偶尔被翻 → 从不修改 |
