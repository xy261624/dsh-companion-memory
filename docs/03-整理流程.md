# 整理流程

整理的目标是把原始会话里的有用内容提炼进对应的记忆文件，同时清掉过时的、重复的、只备查不需要常驻的内容。

## 一、取原料

在工作区根目录运行提取脚本，把新会话从 dsh 的会话日志里取出来，写进待整理目录。

```sh
python scripts/sort_memory.py
```

脚本按游标增量提取，处理过的会话不会重复取。第一次跑带上 `--since-days 7`，否则所有历史会话都会被提出来。

## 二、读会话

把待整理目录里的文件读一遍。这些文件是提取脚本生成的角色与用户对话，读完是否删除放到收尾阶段处理。

## 三、筛选标准

每条内容按同一个标准判断：对未来的角色有没有用，能不能让角色更了解对方、更好帮到对方。

- 有用的：状态变化、对方亲口说的话、新发现、值得记住的事
- 没用的：日常流水账、闲聊、反复推敲的过程

有用的内容再判断一次，判断标准只有一条：角色不主动去读它，会不会误事。

- 会误事：近期要用、重要、不读要出问题的，进记忆库，同时在常驻文件里写一行索引
- 不会误事：有价值但近期用不上，进记忆库即可，不留索引

## 四、分流写入

### STATUS.md

- **现在**：一句话描述对方当前的状态，不加多余描述
- **近期关键事**：想法、情绪、商量、吐槽这类没有明确目标的事
- **待办**：只写对方亲口说要做的事，写清楚做到哪一步、下一步做什么。角色自己的提议和打算另列一栏，不混进待办
- **最近对话情况**：上次实际聊天的时间，中间触发过几次心跳
- **角色栏**：心跳触发后对方在下一次整理前没有回应，记下那次心跳的内容
- 每条写成"极简描述 + 索引"的结构，描述控制在 50 字以内，描述里不放细节
- 不写版本号、路径、命令、时间戳这类技术标识，这些放记忆库

### MEMORY.md

- 只在属性发生变化时修改，没有变化不动
- 记不会变的事：作息、喜好、忌讳、生日、长期目标

### 记忆库

- 主题详情更新到对应文件
- 出现新主题就新建文件
- 单个文件超过 15KB 按话题拆分

### 回忆录

- 值得记住的经历，按时间顺序写成故事

## 五、迭代清理

- STATUS 里已经有结果的事，按情况移进待办、记忆库或者删掉
- 放了一周没用上的条目，删掉或者搬进记忆库
- 暂时搁置、又不影响当前行动的事，不要挂在常驻栏
- 删除文件之前先确认删的是哪一类：角色自己写的草稿，或者内容已经并进记忆库的文件。确认之后把删了哪个文件、内容并到了哪里记进整理日志

## 六、写作规范

1. **不编造，不脑补。** 只有对方亲口说的才算事实，其余是角色的想法和提议，记录时要写清楚"角色认为""角色提议"。
2. **说人话。** 写成给未来的自己看的日记，不写成报告。不用书面语和汇报用语，不缩句，不把一句话写成口诀，不追求对仗排比。句子里要有完整的主语和宾语。
3. **精简。** 常驻文件不放无用信息，善用索引与文件库的分工。
4. **视角。** 状态文件站在角色的角度写，目的是更好地了解对方；叙事文件站在记录故事的角度写。
5. **称呼。** 用角色对他的称呼来写，不用"他""对方"这类中性指代。情感浓度来自这里，整份文件全是"他"，读起来像档案。
6. **图片。** 重要的、以后还要用的图，把工作区 `附件库/` 里的路径写在描述后面。

写完自检以下几条：

- 每句话能不能当面说出口
- 有没有缩句、有没有写成口诀
- 有没有缺少主语或宾语
- 有没有把角色想的写成对方亲口说的
- 视角是否正确
- 称呼是不是角色对他的叫法，有没有通篇写成"他"
- 动词是不是口语里最常用的，有没有用比喻
- 有没有自造的词和说法
- 待办栏里有没有混进角色自己打算的事

## 七、对抗式审查

整理写完、提交之前，开一个子代理当审查员。审查员拿到三份基准：这份整理流程（写作规范在第六节）、工作区 `模板/` 里的标准模板、以及这次改动过的记忆文件。

审查员逐条对照，找出以下问题：

- 脑补：把角色想的写成对方亲口说的
- 条目超长：状态描述超过 50 字
- 汇报腔、缩句、口诀化、缺主语宾语、动词书面化、用比喻
- 自造的词和说法
- 跨栏重复：同一件事在不同栏目或不同文件里重复出现
- 视角错误
- 记忆文件里通篇是中性指代，没有用角色对他的称呼
- 该删没删、该留没留

审查员输出问题清单，每条标注严重程度、引用原文、指出违反哪条规范、给出改法。整理者按清单逐条修改，改完结束。

审查子代理要串行执行，不要和整理过程并行。

## 八、收尾

- 清空待整理目录
- 工作区如果用了 git，把这次的改动提交上去。提交信息先写成文件，再用 `git commit -F` 读它提交，避免多行中文在命令行里出现乱码。提交信息写清楚这次整理了哪些内容、改了哪些文件
