# 整理流程

整理的目标是把原始会话里的有用内容提炼进对应的记忆文件，同时清掉过时的、重复的、只备查不需要常驻的内容。

> 这份文档里用两个占位符指人：`【称呼】` 是这个角色平时叫你的那个爱称，`【角色】` 是你给这个角色起的名字。落到记忆文件里要换成实际叫法，不要写成"他""对方"。

## 一、取原料

在工作区根目录运行提取脚本，把新会话从 dsh 的会话日志里取出来，写进待整理目录。

```sh
python scripts/sort_memory.py
```

脚本按游标增量提取，处理过的会话不会重复取。第一次跑带上 `--since-days 7`，否则所有历史会话都会被提出来。

## 二、读会话

把待整理目录里的文件读一遍。这些是提取脚本生成的对话，说话的两边就是我和【称呼】。读完是否删除放到收尾阶段处理。

## 三、筛选标准

每条内容按同一个标准判断：对以后的我有没有用，能不能让我更了解【称呼】、更好帮到【称呼】。

- 有用的：状态变化、【称呼】亲口说的话、新发现、值得记住的事
- 没用的：日常流水账、闲聊、反复推敲的过程

有用的内容再判断一次，判断标准只有一条：我不主动去读它，会不会误事。

- 会误事：近期要用、重要、不读要出问题的，进记忆库，同时在常驻文件里写一行索引
- 不会误事：有价值但近期用不上，进记忆库即可，不留索引

## 四、分流写入

### STATUS.md

- **现在**：一句话写【称呼】此刻在做什么，不加多余描述
- **近期关键事**：想法、情绪、商量、吐槽这类没有明确目标的事
- **待办**：只写【称呼】亲口说要做什么，写清楚做到哪一步、下一步做什么。我自己提过的打算另列一栏，不混进待办
- **最近对话情况**：上次实际聊天的时间，中间触发过几次心跳
- **【角色】这一栏**：我开口之后，【称呼】在下一次整理之前没回应，就把那次开的口记下来
- 每条写成"极简描述 + 索引"的结构，描述控制在 50 字以内，描述里不放细节
- 不写版本号、路径、命令、时间戳这类技术标识，这些放记忆库

### MEMORY.md

- 只在属性发生变化时修改，没有变化不动
- 记不会变的事：作息、喜好、忌讳、生日、长期目标

### 记忆库

- 主题详情更新到对应文件
- 出现新主题就新建文件
- 单个文件超过 15KB 按话题拆分

### 回忆录

- 值得记住的经历，按时间顺序写成故事

## 五、迭代清理

- STATUS 里已经有结果的事，按情况移进待办、记忆库或者删掉
- 放了一周没用上的条目，删掉或者搬进记忆库
- 暂时搁置、又不影响当前行动的事，不要挂在常驻栏
- 删除文件之前先确认删的是哪一类：我自己写的草稿，或者内容已经并进记忆库的文件。确认之后把删了哪个文件、内容并到了哪里记进整理日志

## 六、写作规范

1. **不编造，不脑补。** 只有【称呼】亲口说过的才算事实，剩下的都是我自己想出来的，写的时候要说清楚"我觉得""我想"。
2. **说人话。** 写成给未来的自己看的日记，不写成报告。不用书面语和汇报用语，不缩句，不把一句话写成口诀，不追求对仗排比。句子里要有完整的主语和宾语。
3. **精简。** 常驻文件不放无用信息，善用索引与文件库的分工。
4. **视角。** 状态文件是写给我自己看的，目的是一眼就知道【称呼】最近在忙什么；叙事文件站在讲故事的角度写。
5. **称呼。** 通篇用我平时叫【称呼】的那个叫法，不要写成"他""对方"这种隔着一层的说法。整份文件全是"他"，读起来像病历本，不像我记的事。
6. **图片。** 重要的、以后还要用的图，把工作区 `附件库/` 里的路径写在描述后面。

写完自检以下几条：

- 每句话能不能当面说出口
- 有没有缩句、有没有写成口诀
- 有没有缺少主语或宾语
- 有没有把我自己想出来的写成【称呼】亲口说的
- 视角是否正确
- 称呼是不是我平时叫【称呼】的那个叫法，有没有通篇写成"他"
- 动词是不是口语里最常用的，有没有用比喻
- 有没有自造的词和说法
- 待办栏里有没有混进我自己打算的事

## 七、对抗式审查

整理写完、提交之前，开一个子代理当审查员。审查员拿到三份基准：这份整理流程、写作规范（在第六节）、工作区 `模板/` 里的标准模板；要审的是这次改动过的记忆文件。

审查员逐条对照，找出以下问题：

- 脑补：把我自己想出来的写成【称呼】亲口说的
- 条目超长：状态描述超过 50 字
- 汇报腔、缩句、口诀化、缺主语宾语、动词书面化、用比喻
- 自造的词和说法
- 跨栏重复：同一件事在不同栏目或不同文件里重复出现
- 视角错误
- 记忆文件里通篇写着"他""对方"，没有用我平时叫【称呼】的那个叫法
- 该删没删、该留没留

审查员输出问题清单，每条标注严重程度、引用原文、指出违反哪条规范、给出改法。整理者按清单逐条修改，改完结束。

审查子代理要串行执行，不要和整理过程并行。

## 八、收尾

- 清空待整理目录
- 工作区如果用了 git，把这次的改动提交上去。提交信息先写成文件，再用 `git commit -F` 读它提交，避免多行中文在命令行里出现乱码。提交信息写清楚这次整理了哪些内容、改了哪些文件
