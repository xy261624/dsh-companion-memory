# 上手

## 环境要求

- Node.js `^22.19.0 || >=24`
- DeepSeek Harness `0.2.0` 及以上，web 或 desktop profile。开发和验证用的是 `0.2.0-rc.2`，底下的 cordis 是 `4.0.4`
- Python 3.8 以上，装一个依赖：`pip install zstandard`

## 一、装插件

```sh
dsh plugin --profile web add github:xy261624/dsh-companion-memory
dsh --profile web
```

包里的 `cordis.patch.yml` 会把两个插件插进组合，装完就在跑。

**装完第一件事是把模式 id 改成你自己的。** 两个插件默认都写 `default`，dsh 不自带这个名字，对不上的时候会话开不出来，只在日志里留一行错误，界面上看不到任何提示。先看一下自己的模式有哪些：

```sh
# Windows
dir "%USERPROFILE%\.dsh\.agent-presets"

# macOS / Linux
ls ~/.dsh/.agent-presets
```

然后在 profile 的 `cordis.patch.yml` 里写：

```yaml
- id: companion-memory-heartbeat
  config:
    defaultPreset: 你的模式id

- id: companion-memory-auto-sort
  config:
    sortPreset: 你的模式id
```

其余字段不写就用默认值。

### 心跳插件的配置

| 字段 | 默认值 | 说明 |
|---|---|---|
| `workspace` | dsh 里的第一个工作区 | 记忆文件所在的工作区 |
| `stateDir` | `<workspace>/.state` | 状态文件和预设文件的目录，两个插件要指向同一个 |
| `presetFile` | `<stateDir>/heartbeat-preset.json` | 读哪个模式开工，由自动整理插件写入 |
| `stateFile` | `<stateDir>/heartbeat-state.json` | 会话指纹缓存，可以随时删 |
| `defaultPreset` | `default` | 预设文件读不到时用哪个模式，必须改成你环境里存在的 id |
| `checkIntervalMs` | `120000` | 多久检查一次。改这个值会同时改变实际触发频率，概率曲线是按 2 分钟一轮折出来的 |
| `activeThresholdHours` | `0.5` | 距上次对话少于这个小时数就不打扰 |
| `sleepStartMinutes` | `1440` | 静默区间起点，按当天分钟数算。静默区间只能跨午夜：起点写 0 到 1439，终点写起点之前；`1440` 表示不设起点、只静默到终点 |
| `sleepEndMinutes` | `600` | 静默区间终点，600 是 10 点 |
| `maxProbability` | `0.9` | 累积概率上限 |
| `backoffDenominator` | `3.0` | 概率增长速度，值越小触发越频繁 |
| `delayMaxMs` | `290000` | 命中后随机延迟的上限 |
| `titles` | 六个默认标题 | 会话标题库 |
| `permissionPreset` | `danger-full-access` | 心跳会话的权限档，取值见下面「权限」一节 |
| `prompt` | 内置一段 | 覆盖注入的提示词，`{hours}` 会替换成距上次的小时数 |

### 自动整理插件的配置

| 字段 | 默认值 | 说明 |
|---|---|---|
| `workspace` | dsh 里的第一个工作区 | 工作区，要和心跳插件配成同一个 |
| `stateDir` | `<workspace>/.state` | 状态文件和预设文件的目录，两个插件要指向同一个 |
| `stateFile` | `<stateDir>/auto-sort-state.json` | 上次整理时间与指纹缓存 |
| `presetFile` | `<stateDir>/heartbeat-preset.json` | 整理完写这里，必须和心跳插件指向同一个文件 |
| `memoryGuide` | `记忆库/记忆系统说明.md` | 整理会话第一份要读的文件 |
| `sortProcess` | `整理流程.md` | 整理流程 |
| `extractScript` | `scripts/sort_memory.py` | 提取脚本 |
| `sortPreset` | `default` | 整理会话用哪个模式，必须改成你环境里存在的 id |
| `skipPresets` | `[]` | 这些模式的会话不提取，会作为 `--skip-presets` 传给脚本 |
| `checkIntervalMs` | `180000` | 多久检查一次 |
| `quietThresholdMs` | `1800000` | 静默多久才整理 |
| `permissionPreset` | `danger-full-access` | 整理会话的权限档 |
| `prompt` | 内置一段 | 覆盖注入的整理指令 |
| `pythonCommand` | `python` | 跑脚本用的解释器 |

两个插件的 `workspace` 要配成同一个。只配了一个的话，另一个会退回 dsh 里的第一个工作区，两份 `presetFile` 落到不同目录，整理写下的模式心跳读不到。

两个插件的 `presetFile` 也必须一致，否则结果同上。

### 权限

两个插件默认以 `danger-full-access` 开会话。原因是它们常常在你不在电脑前的时候自己开，没法逐次批权限。

影响范围只有插件开的那一个会话，日常会话不受影响。想收紧的话，把 `permissionPreset` 改成 dsh 里更小的权限档。

## 二、建目录

在工作区根目录建这几个东西：

```
工作区/
  STATUS.md
  MEMORY.md
  整理流程.md
  .gitignore
  记忆库/
    记忆系统说明.md
  模板/
    STATUS.md
    MEMORY.md
    回忆录.md
    记忆库/
      条目模板.md
  scripts/
    sort_memory.py
  待整理/
  回忆录-2026.md
```

从仓库复制到工作区的对应关系：

| 仓库里的 | 工作区里的 |
|---|---|
| `templates/STATUS.md` | `STATUS.md` |
| `templates/MEMORY.md` | `MEMORY.md` |
| `templates/记忆库/记忆系统说明.md` | `记忆库/记忆系统说明.md` |
| `templates/回忆录.md` | `回忆录-2026.md` |
| `templates/` 整个目录 | `模板/`（留着不动，当审查基准） |
| `docs/03-整理流程.md` | `整理流程.md` |
| `scripts/sort_memory.py` | `scripts/sort_memory.py` |

`模板/` 那一份是留给审查子代理当基准用的，不要往里面写内容。`模板/记忆库/条目模板.md` 是新建记忆库文件时照抄的骨架。

工作区如果要用 git 管理，先把这份 `.gitignore` 放进根目录：

```
.state/
待整理/
*.log
```

`待整理/` 里是整段对话原文，`.state/` 里是会话 id 和路径，两样都不该进版本库。

模板里只有结构，内容要你自己和角色一起填。模板里写的是"他"，填的时候换成角色对他的称呼，写作规范不接受通篇的中性指代。

先按模板把已经知道的事写上去，其余内容由整理逐步补充。整理结果不符合预期时，把对应的要求补进整理流程或者写作规范。

## 三、配模式

模式文件在 `~/.dsh/.agent-presets/<模式名>/agent.cordis.yml`。把两份常驻文件加进注入名单：

```yaml
- id: agent-instructions
  config:
    maxBytes: 65536
    instructionFileCandidates:
      - AGENTS.md
      - MEMORY.md
      - STATUS.md
```

`instructionFileCandidates` 是整体替换，不是追加。默认值是 `AGENTS.md` 和 `CLAUDE.md`，上面这份配置里不写 `AGENTS.md` 的话，工作区原有的 AGENTS.md 就不再注入了。所以要把它一起列进去。

`maxBytes` 是这两份文件合计的渲染预算，超出的部分会被截断，而且没有任何提示。常驻文件要写短，原因就在这里。

## 四、第一次整理

先和角色正常聊几次，积累一些对话。然后手动跑一次：

```sh
cd "D:/your/workspace"
python scripts/sort_memory.py --since-days 7
```

脚本会把新对话提取到 `待整理/`。然后开一个新会话，把 `整理流程.md` 指给它，让它照着做一遍。

第一次跑务必带上 `--since-days`，不加的话脚本会把所有历史会话都提出来，几百个文件进到待整理目录，一个整理会话读不完。

第一次整理之后检查结果，结果不对的按上一节的办法处理。

## 五、自动整理

插件装上就在跑，没有单独的开关。默认静默 30 分钟、每 3 分钟检查一次，条件够了就自己开整理会话。

想先关掉、等手动跑通一次再打开，在 profile 的 `cordis.patch.yml` 里加一行：

```yaml
- id: companion-memory-auto-sort
  disabled: true
```

确认没问题之后把这行删掉。

## 六、心跳

插件同样装上就在跑。心跳需要知道用哪个模式开口，这个写在预设文件里：

```json
{
  "preset": "你的模式id",
  "updatedAt": 1750000000000
}
```

文件不存在时会退回 `defaultPreset`，所以这个文件不是必须的。自动整理跑完之后会更新它。

想先关掉：

```yaml
- id: companion-memory-heartbeat
  disabled: true
```

心跳默认 0.5 小时以内有对话就不打扰，0 点到 10 点静默。想让它触发得更频繁，把 `backoffDenominator` 调小；想让它触发得更少，把这个值调大，或者把静默区间拉宽。

心跳会话默认带全权限，原因和改法见上面「权限」一节。

## 七、确认插件起来了

启动之后看日志，两个插件的加载各有一条：

```
heartbeat: plugin loaded
auto-sort: plugin loaded
```

另外工作区里的 `.state/` 目录会被创建出来，这也是旁证。

两条日志都没有，说明插件没挂上，先检查 profile 对不对、包名有没有写错。

## 脚本参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--workspace` | 脚本上一层的目录 | 工作区，会话的 cwd 要跟它一致 |
| `--sessions-root` | `~/.dsh/sessions` | dsh 会话日志目录，`DSH_HOME` 改过的话必须传 |
| `--cursor` | `<工作区>/.state/cursor.json` | 提取游标 |
| `--pending` | `<工作区>/待整理` | 输出目录 |
| `--workspace-state` | `~/.dsh/storages/workspace.json` | 归档会话列表，`DSH_HOME` 改过的话必须传 |
| `--skip-presets` | 空 | 这些模式的会话不提取，多个用空格隔开 |
| `--skip-title-prefix` | `📦 记忆整理` | 标题以这些前缀开头的会话不提取，多个用逗号隔开 |
| `--since-days` | 不限 | 只提取最近这么多天内的对话 |
| `--user-label` | `对方` | 待整理文件里怎么标对方 |
| `--role-label` | `角色` | 待整理文件里怎么标角色 |

`--user-label` 和 `--role-label` 建议改成角色对他的称呼，这样整理会话读到的原料里就有称呼，不容易被中性指代带跑。

## 常见问题

**日志里找不到 `plugin loaded`。**

插件没挂上。检查 profile 名字、包名，以及 `cordis.patch.yml` 里的条目有没有被别的配置覆盖。

**整理会话开起来了，但什么都没做。**

先看插件日志里有没有 `agent-preset/not-found`，那是 `sortPreset` 写错了。再检查 `memoryGuide`、`sortProcess`、`extractScript` 三个路径和 `python` 命令。

**心跳一直不触发。**

按这个顺序查：日志里有没有插件加载记录；`defaultPreset` 是不是你环境里存在的模式 id；现在是不是在静默时段；状态文件里的时间对不对。间隔是从最后一次对话算起的，不是固定周期。

**整理完记忆文件没变化。**

看提取脚本的输出，`待整理/` 里有没有东西。没有的话把 `.state/cursor.json` 删掉重跑，或者用 `--since-days` 限定一个范围。

**记忆文件里通篇是"他""对方"。**

称呼该用角色对他的叫法。在整理流程的写作规范里强调这一条，或者在审查清单里加上这一项。提取脚本那边同时用 `--user-label` 和 `--role-label` 传上称呼，能减少整理时被带跑。
