# 对抗式审查

## 为什么写和审要分开

整理的人刚写完一段，脑子里还是当时的语境，读自己写的东西会自动补上缺的部分，看不出问题。

更麻烦的是我知道自己想写什么，看到文字不达标也会觉得意思传到了。审查要判断的是：没参与整理的人只看文字，能不能读到同样的内容。

所以审查交给一个没有参与整理的子代理。它只有文件和规范，没有当时的语境，只能按文字本身判断。

## 审查员拿到的基准

三份，路径都要写进审查任务里：

1. **整理流程**（工作区里的 `整理流程.md`）：规定了每份文件该写什么、条目该多长、索引怎么留。用来判断内容放错位置、条目超长、该留没留这类问题。
2. **写作规范**（同一份文件的第六节）：规定了要写成什么样。用来判断汇报腔、口诀化、缺主语宾语、自造词这类问题。
3. **标准模板**（工作区里的 `模板/` 目录）：每份文件的结构骨架，标明每一栏该写什么。用来判断格式和归类，比如该进待办的事是不是写进了近期关键事、有没有留索引。模板里用 `【称呼】` 和 `【角色】` 标出该出现叫法的位置，被审文件里对应的位置要是实际叫法，写成"他""对方"就算不合格。

整理流程管内容和位置，写作规范管写法，模板管格式，三份都要过一遍。

## 要挑的几类问题

### 脑补

把我自己想出来的写成【称呼】亲口说的。这是最严重的一类，因为它会污染整份记忆，之后所有基于这条的推理都是错的。

判断方法：这条事实，能不能在原始对话里找到【称呼】说的原话。找不到就是脑补。

### 条目超长

极简描述超过 50 字，或者描述里塞了细节。

判断方法：数一下句子长度；再看这条描述是不是已经把"详情在 xxx.md"里的内容说了一半。

### 汇报腔和口诀化

典型症状：

- 短句成篇，每句一个意思，读起来像 PPT
- 对仗排比，前后两句结构一样
- 把一句话压缩成一个口号
- 用动词名词化的说法，比如"进行了一次确认"

判断方法：这段话能不能当面说出口。人对人说话不会这么说，就是不合格。

### 缺主语宾语

"写完了""改好了""没问题"这种，谁写完的、改的什么，全是空的。

判断方法：每句话找一遍主语。

### 视角错误

状态文件是写给自己的，目的是一眼就知道【称呼】最近在忙什么；叙事文件该站在记录故事的角度写。

常见错误有两个：状态文件写成第三方的档案记录，叙事文件写成流水账。

### 隐喻和自造词

用比喻代替直白的说法，或者自己造一个词当术语用。

判断方法：这个词是不是日常对话里会出现的。不是就换成日常说法。

### 跨栏重复

同一件事在不同栏目或者不同文件里重复出现。状态文件写了一遍，文件库里又写了一遍细节，属性文件里还提一句。

判断方法：列一个清单，把同一件事的所有出现位置找出来，只留一处。

### 该删没删

事情办完了、话题过去了、条目放了一周没用上，还挂在常驻文件里。

## 输出格式

审查员交一份问题清单，每条包含四项：

| 字段 | 内容 |
|---|---|
| 严重程度 | 高 / 中 / 低 |
| 原文 | 引用有问题的原句 |
| 违反的规范 | 指出违反了上面哪一类 |
| 改法 | 给出可以直接替换的句子，或者明确的修改方向 |

改法这一项不能省。只说"这句不像人话"没有用，要说清楚换成什么。

整理者拿到清单之后逐条改，改完结束。不需要再跑一轮审查，除非问题清单里有高严重程度的问题被改动过大。

## 怎么跑

用 subagent 工具开一个子代理，把三份基准的路径写进任务描述里，让它逐条对照。

要求串行执行：子代理跑完、拿到结果之后，整理者再动手。不要和整理过程并行，也不要一次开多个审查员，每个审查员看到的文件版本不一样，结论会打架。

## 审查员常犯的错

常见的问题：

- 把符合规范的写法当成问题（比如把口语化的长句当成啰嗦）
- 提出的改法反而更差
- 漏掉真问题，挑了一堆无关紧要的

所以问题清单要人工过一遍。
